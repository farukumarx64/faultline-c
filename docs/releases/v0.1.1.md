# Faultline v0.1.1

**Install Faultline's commands and use them from any directory.**

This release adds source installation and removal for the CLI, coordinator, and
worker. It builds on v0.1.0 without changing job execution, the wire protocol,
the WAL format, or the existing recovery guarantees.

## What changed

- **`make install`:** builds all three executables as needed and copies them to
  the chosen command directory with executable permissions.
- **Configurable destinations:** `PREFIX` defaults to `/usr/local`; `BINDIR`
  defaults to `$(PREFIX)/bin`. `DESTDIR` supports staged installation, and
  destination paths containing spaces are supported when quoted.
- **`make uninstall`:** removes only the three command paths, preserving WALs,
  directories, and unrelated files. It requires no compiler or existing build.
- **Installation documentation:** personal and system installation, `PATH`
  setup, fixed WAL locations, updates, removal, and troubleshooting.
- **Regression coverage:** six installation checks, with a new step in both
  Linux CI configurations and retained `install.log` output.

## Install and try it

This is a **source release** for macOS and Linux. Download and extract the
release's source archive, then run the following from the extracted directory.
You need Make, a C11 compiler, POSIX sockets/threads, and the platform's `install`
utility. Python 3.9+ is needed only for tests and the automated demo.

```sh
make install PREFIX="$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
faultline --help
```

Add the `export PATH=...` line once to your shell's startup configuration
(`~/.zshrc` for zsh) so new terminals can find the commands.

For a new coordinator state, start these in separate terminals:

```sh
# Terminal 1: initialize a new WAL once.
mkdir -p "$HOME/.local/state/faultline"
faultline-coordinator --wal "$HOME/.local/state/faultline/coordinator.wal" --init-wal

# Terminal 2
faultline-worker

# Terminal 3
faultline ping
faultline submit sleep --args 1000 --max-retries 1
faultline status 1
```

Use the job ID returned by submission. Status is a snapshot; repeat the query
if the job is still queued or running. A completed example returns `state=DONE`
and `result="slept_ms=1000"`.

On restart, reuse the same absolute WAL path **without** `--init-wal`, then
start workers again. If you already have a v0.1.0 WAL, use its absolute path
instead of initializing a new one to keep your saved jobs.

To remove a personal installation, run this from the extracted source directory:

```sh
make uninstall PREFIX="$HOME/.local"
```

## Verification

All **six installation checks passed locally on macOS in both normal and
AddressSanitizer/UBSan builds**, using `CFLAGS='-O0 -g -Werror'`:

```sh
make test-install CFLAGS='-O0 -g -Werror'
make SANITIZE=1 test-install CFLAGS='-O0 -g -Werror'
```

The suite builds in a fresh temporary source tree and verifies installation,
staging, replacement, error propagation, and selective removal. Its live check
uses installed commands through `PATH` from separate directories while the
original checkout path is unavailable. It verifies a real job's exact result,
unknown-ID behavior, and recovery of the same result after coordinator restart.

Linux CI now includes this suite in its GCC 13 and Clang 18 + ASan/UBSan jobs,
under a 90-second deadline. The
[release checklist](https://github.com/farukumarx64/faultline-c/blob/v0.1.1/docs/release-checklist.md#v011-local-release-preparation)
records local preparation and the remaining hosted validation. Earlier full-suite
and benchmark evidence retains its original revision and scope.

## Compatibility and scope

The runtime C sources and headers are unchanged from v0.1.0, so existing WALs
require no migration. Stop running workers and the coordinator before replacing
their executables; restart using the retained WAL afterward.

Installation retains the normal `-O0 -g` build defaults. It does not start
background services, change the default WAL location, or configure the shell.
The engine still runs on IPv4 loopback with the same bounded at-least-once
retry policy and durability limits.

Homebrew distribution, prebuilt executables, and service management are not
included in this release. GitHub's source archives contain the source,
documentation, and tests.
