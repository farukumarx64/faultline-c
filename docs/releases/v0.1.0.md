# Faultline v0.1.0

**The first MVP release of Faultline: an open-source job execution engine in C11
with worker failure detection, bounded retries, and durable coordinator recovery.**

Faultline runs a coordinator, independent workers, and a CLI as separate processes.
This release targets macOS and Linux on one machine using IPv4 loopback.

## What is included

- **Job execution:** FIFO scheduling across idle workers, with built-in `sleep`,
  `prime_count`, `fibonacci`, and `hash` tasks.
- **Worker recovery:** configurable heartbeats, disconnect and timeout detection,
  automatic reassignment within the job's retry allowance, and rejection of
  outdated attempt reports. Defaults are two-second heartbeats and a six-second
  timeout.
- **Persistence:** a checksummed write-ahead log, durable submission and result
  acceptance, replay after coordinator restart, incomplete-tail repair, and
  recovery of interrupted assignments according to the retry policy.
- **Inspection:** `faultline ping`, `submit`, `status`, `jobs`, `workers`, and
  `stats`, plus structured lifecycle logs.
- **Reproducible evidence:** failure and crash tests, seeded worker churn,
  reviewed scaling/recovery benchmarks, an architecture diagram, and a recorded
  worker-crash demonstration.

## Build and try it

This is a **source release**. Build with Make and a C11 compiler with POSIX
sockets and threads; no third-party C libraries are required. Tests and the
automated demo also require Python 3.9+.

```sh
git clone --branch v0.1.0 --depth 1 https://github.com/farukumarx64/faultline-c.git
cd faultline-c
make
```

Start the coordinator in one terminal, creating a fresh log:

```sh
./build/debug/faultline-coordinator --port 9000 --wal faultline.wal --init-wal
```

Start a worker in another terminal; repeat to add workers:

```sh
./build/debug/faultline-worker
```

Submit and inspect from a third terminal:

```sh
./build/debug/faultline ping
./build/debug/faultline submit sleep --args 1000 --max-retries 1
./build/debug/faultline status 1
```

Use the job ID printed by submission; a fresh log starts at 1. Status is a
snapshot, so query again if the job is still running. Expected completion is
`state=DONE` with `result="slept_ms=1000"`. On coordinator restart, keep the WAL
and omit `--init-wal`. Start workers again to establish new connections.

For an automated recovery demonstration:

```sh
make demo-recovery
```

It submits one job, kills its busy worker with SIGKILL, and verifies that an
already-connected worker completes the same job ID on attempt 2. It records
the exchange and cleans up its owned processes.

## Verification and measured results

The release review passed **131 C test groups and 143 process integration
scenarios** in both normal and ASan/UBSan builds on macOS, plus **45 demo and
benchmark-verifier checks per build**. The fresh-checkout quick start, restart,
all four task results, and recorded recovery demo were verified.

Linux CI runs on Ubuntu 24.04 with GCC 13 and Clang 18 + ASan/UBSan. It treats
warnings as errors and checks the core suites, deadline handling, batch/chaos
verifiers, and a seed-42 experiment with 100 jobs, preserving available evidence
after success or failure. The release checklist records the reviewed runs and
the limits of the checks.

Measured on an **Apple M4, 10 cores, 16 GiB RAM, macOS 27.0.1**, using Apple
Clang 21, `-O2 -g -Werror`, sanitizers off, normal WAL synchronization, AC power,
and Low Power Mode off. Each configuration has five measured repetitions.

| Workers | Median time for 64 `prime_count(10000000)` jobs | Median jobs/s | Speedup |
| ---: | ---: | ---: | ---: |
| 1 | 59.008 s | 1.085 | 1.000× |
| 2 | 29.856 s | 2.144 | 1.976× |
| 4 | 16.924 s | 3.782 | 3.487× |
| 8 | 13.942 s | 4.590 | 4.232× |

All 1,536 scaling jobs, including warmups, completed correctly. In the separate
four-worker recovery campaign, all 576 jobs completed. Median observed detection
was **11.119 ms for SIGKILL** and **5,195.880 ms for heartbeat expiry**; median
paired extra completion time was **0.418 s** and **5.691 s**, respectively.
Detection includes durable logging and observation delay. Reassignment also
includes FIFO waiting. These are observations for the documented workloads and
machine, not multi-host or universal performance claims.

## Guarantees and current limits

Acknowledged jobs and accepted terminal results are synced to the WAL before
publication and recover after coordinator process crashes with the same retained
log and working storage. Execution uses **bounded at-least-once retries**: work
can run again, and attempt checks protect coordinator state rather than making
external effects happen exactly once. A missing submission ACK leaves an
uncertain outcome; submitting again can create another job.

The MVP has one coordinator, no automatic failover or worker reconnection, and
no authentication or TLS. Networking is loopback-only. It retains at most
256 jobs, allows 64 simultaneous worker/CLI connections, and limits arguments
and results to 1,024 bytes each. There is no WAL compaction, job eviction,
independent execution deadline, arbitrary shell execution, or web dashboard.
Disk loss and universal power-loss survival are outside the durability contract.

Prebuilt binaries, installation commands, and background service management are
not included. GitHub's source archives and the tagged repository contain the
source, documentation, tests, and reviewed reports.
